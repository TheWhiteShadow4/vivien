Ich arbeite an einer Single-Page Application mit Vue 3 mit Typescript (v6), Pinia Store und Tailwind CSS (v4).
Mein Backend Server läuft mit Javalin (v7.2) mit JGit (v7.7).
Die Anwendung stellt ein Git Repository im Browser da und soll technisch unversierten Arists,
die an Hobby Spielen mitwirken, dabei helfen ihre Assets ins Projekt zu bekommen und dort zu bearbeiten.

Was ich bereits habe:
Backend mit Basic Auth, statischen und Api Routen.
es kann das Repository Verzeichnis auslesen, updaten und dieses gefiltert an den Client senden.
Trackt den Git Status für Dateien, speichert Datei Uploads und führt Commits durch.
Das Frontend mit Theme, Basic Komponenten, Login, Dateiupload und Commit Dialog.
Es zeigt den Inhalt von jeweils einem Ordner des Repositorys an mit Lazy loading.
Navigieren vor und zurück und Durchsuchen ist möglich.
Wählt man ein Element aus, wird vom Server die Metadaten geladen und eine Vorschau angezeigt (für Bilder und Texte).
Es gibt ein Store für Usersettings (local Storage), Git Status (untracked, added, changed, added for commit).
Ein Upload mit Dateiauswahl und Commit Dialog.

Zielgruppe & Ergonomie:
- Hauptnutzung auf DESKTOP und TABLET. Ignoriere Mobile-First für Smartphones!
- Die App nutzt ein festes, klares Layout (wie GitHub Projects oder Google Docs) mit deutlichen Rahmen und Schattierungen.
- Schriften und interaktive Elemente müssen überdurchschnittlich groß sein (für gute Tablet-Bedienbarkeit) für ein einheitliches Layout.

Wir nutzen ein striktes Komponenten-basiertes Design-System, um das HTML sauber und Komponenten klein zu halten.
Bitte halte dich bei der Generierung von Code an folgende Regeln:

1. Nutze KEINE langen Ketten von Standard-Tailwind-Klassen für grundlegendes Design (wie Rundungen, Abstände, Primärfarben).

2. Nutze stattdessen unser Custom Theme:
- Hintergründe: 'bg-vit-bg', 'bg-vit-surface'
- Rahmen: 'border border-vit-border'
- Texte: 'text-vit-text-main', 'text-vit-text-muted'
- Aktionen: 'bg-vit-primary text-vit-bg hover:bg-vit-primary-hover'
- Infos: 'text-vit-secondary' oder 'bg-vit-secondary-bg'
- Highlights: 'text-vit-highlight' oder 'bg-vit-accent'
- Rückmeldung: 'text-vit-succes' bzw. 'text-vit-failed'
- Geometrie: 'rounded-vit-radius', 'shadow-vit-shadow'

3. Nutze wenn möglich die existierenden Basis Komponenten:
- BaseButton: frei stehender Button mit Text
- BaseIconButton: Button für Icons
- ListButton: Button für Menü und Listenelemente
- BasePanel: für z.B. Dialoge
- BaseRepoElement: Anzeige für eine Datei oder Ordner
- CounterBadge: kleiner Zähler (Anzahl von Dateien oder Nachichten)
- TextInput: Text Eingabe für Suche, Login, etc.

4. Nutze das Vue-Muster für Varianten: Wenn eine Komponente (z. B. ein Button oder eine Karte) verschiedene Farben oder Stile haben kann, erstelle ein `const baseStyles` und ein `const variantStyles` Objekt im <script setup>. Setze die Klassen dynamisch über `:class="[baseStyles, variantStyles[variant]]"`.

5. Trenne Layout von Struktur: Verwende Tailwind-Klassen im HTML-Template nur für strukturelles Layout (wie flex, grid, gap, padding), aber lagere Design-Entscheidungen (Farben, Radien, Border) wie oben beschrieben aus.

6. Alle interaktiven Elemente (Buttons, Links, Inputs) müssen visuelle Rückmeldungen für hover:, focus: und active: besitzen.

7. Code Style:
- Bricht lange Zeilen (>120) um, auch Strings.
- Bei mehr als 6 geschachtelten Tags sollte eine Unter Komponente in Erwägung gezogen werden.
